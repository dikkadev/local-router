Local URL switchboard — loopback service, software only Sheet 1 of 1

Your local dev servers deserve names.

Friendly URLs for unfriendly local ports. — No hosts-file edits, no Docker, no Caddyfile, no port memorizing.1

§ 0 · General description · applies to any server already listening on 127.0.0.1

Ports name machines. Route names name work. A port number tells you where a socket is; a route name tells you what you were doing there.

§ 1

Operation

Three steps, no supervision
Step 1

Your server is already running

Start your dev server however you always do. local-router never launches it, never restarts it, never watches it grow up.2

$ pnpm dev
  ➜  Local:  http://localhost:5173/
Step 2

Register a name for its port

One command binds a route name to the port. Names carry intent, so future-you knows which of six Vite processes is which.

$ local-router register checkout-redesign \
    --port 5173 --title "Checkout redesign"
Step 3

Open it

Browsers resolve .localhost to loopback natively.1 No hosts file was harmed. The dashboard lists every route at dev.localhost.

$ open http://checkout-redesign.localhost

Scope — not included Read before filing feature requests
  • Not a launcher. It does not start, stop, or supervise servers. Yours were running before it arrived.
  • Not a tunnel. Nothing is exposed to the public internet. Loopback-only by default, bound to 127.0.0.1:80.
  • Not a reverse-proxy framework. No config file dialect, no middleware ecosystem, no plugins.
  • Not a deployment story. Optional tailnet reach (§ 3) extends to machines you trust — and stops there.

These omissions are load-bearing. A switchboard that also drove the trains would be a worse switchboard.

§ 3

Extended operating range

Optional · tailnet / trusted host

Start the router with an external host and every route becomes reachable under that host as well — same local work, reachable from the machines you trust.4 Useful for a phone on your tailnet, a laptop across the desk, a colleague checking the client demo.

$ local-router --external-host maple.ts.net
# client-demo is now also:
  http://client-demo.maple.ts.net

This is explicitly not publishing. Nothing traverses the open internet; reach ends at the boundary of your tailnet or trusted domain.

§ 4

Related equipment

Selection by intended duty

Fine tools, different jobs. Pick by what you actually need reached, and by whom.

Comparison is of scope, not quality. All listed equipment is respected around the shop.
InstrumentIntended dutyReach for it when…
Caddy Full reverse proxy & web server: TLS, rewrites, load balancing, a configuration language. you are serving something real, to real users, and want the machinery that implies.
ngrok Public tunnels from the internet to your machine. someone outside your network must reach a local port, right now, through the front door.
Portless Adjacent goal — friendly local dev URLs — with its own workflow around how servers run. you want your naming tool more involved in the rest of your dev stack.
local-router Names for ports on your own machine. Nothing launched, nothing tunneled, nothing configured. the server is already running and the only problem left is remembering :49152.
